# Решения за владельцем

Что сделано — в README. Ниже только то, что требует решения или действия владельца (ничего из этого не выполнено).

## Нужно решить до запуска

1. **VPS.** Отдельный сервер (основной 2 vCPU / 3.8 ГБ не подходит). Рекомендация для 10 параллельных задач: 16–24 vCPU / 48 ГБ / 250 ГБ NVMe; для старта на 3 задачи — 8 vCPU / 16 ГБ / 100 ГБ. Ubuntu 24.04. Провайдер и тариф — выбор владельца; после выбора — `deploy/bootstrap.sh`.
2. **Домен.** `agents.tkbk.online` (в `.env` и Caddyfile) — или другой; DNS A-запись до запуска.
3. **Квоты часов.** Берутся из `license.ts` сайта: Pro 20 ч, Teams 100 ч, Teams+ 300 ч в месяц; в оркестраторе — `limits.cloudAgentHours` из ответа лицензии, запасной словарь на случай отсутствия поля. Если часы в тарифах меняются — менять на сайте, оркестратор подхватит. Параллельно на ключ: Pro 3, Teams 5, Teams+ 10 (`CONCURRENT_PER_PLAN`) — подтвердить.
4. **Общий бюджет Teams.** Сейчас часы считаются на каждый ключ команды отдельно (ответ `/api/license/check` не содержит `sub` владельца команды). Для общего пула сайту нужно добавить в payload поле `teamSub` (или `owner`), оркестратору — считать минуты по нему. Одна правка с обеих сторон; до неё Teams = 100 ч на каждый ключ (щедрее, чем задумано).
5. **Деплой лицензий на сайте.** `POST https://tkbk.online/api/license/check` на проде отвечает 404 — коммит `0964ad0` (Free/Pro/Teams) на main сайта не задеплоен. Без него облачные задачи недоступны всем (403). Деплоить сайт — по его процедуре (`scripts/deploy.py` из tkbk-main).
6. **Подпись лицензий.** Задать `LICENSE_PUBLIC_KEY` (публичный Ed25519-ключ сайта, база64 raw 32 байта — показывается в админке) — тогда подделать ответ сайта по пути нельзя. Без него доверяем TLS.
7. **HMAC-секрет** для бота/сайта/панели: свой `AGENTS_INTERNAL_SECRET` (рекомендую) или общий `EA_INTERNAL_SECRET` бота (код принимает оба имени). IDE секрет не нужен — Bearer `cr_…`.
8. **Модель по умолчанию** — `claude-sonnet-5`; проверить, что имя есть в `/v1/models` шлюза.
