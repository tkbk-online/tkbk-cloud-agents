# Решения за владельцем

Что сделано — в README. Ниже только то, что требует решения или действия владельца (ничего из этого не выполнено).

## Нужно решить до запуска

1. **Ставить ли на сервер TKBK.** Compose готов, локально проверен. Нужны: DNS `agents.tkbk.online`, ~12 ГБ свободной RAM под 3 сэндбокса (или `MAX_CONCURRENT_TASKS=1` и `SANDBOX_MEMORY=3g` на старте), правка Caddyfile на месте. Альтернатива — отдельный VPS под агентов (лучше по безопасности: общий хост с сайтом и ботом = общее ядро).
2. **Секрет HMAC.** Отдельный `AGENTS_INTERNAL_SECRET` (рекомендую) или тот же `EA_INTERNAL_SECRET`, что у бота (меньше настроек, больше радиус поражения при утечке). Код принимает оба имени.
3. **Авторизация из IDE.** В расширение HMAC-секрет класть нельзя. Варианты: (а) сайт/панель подписывает запросы за клиента; (б) добавить в оркестратор `Authorization: Bearer cr_…` для `/v1/tasks*` с лимитом на ключ, HMAC оставить для бота/сайта/`/v1/usage`. Рекомендую (б) — одна правка в `auth.py`, тесты есть.
4. **GitHub-токен клиента в боте.** Для PR из Telegram нужен токен клиента: хранить в боте (шифрованно) или только `deliver=archive` из Telegram, а PR — из IDE, где токен даёт VS Code. Рекомендую второе на старте.
5. **Тарифы и квоты.** Предложение в README (9 900 / 19 900 / 29 900 ₽, Teams с общим бюджетом). Квоты часов должна проверять панель по `GET /v1/usage`; в оркестраторе только страховочный `MONTHLY_MINUTES_CAP_PER_KEY`.
6. **Модель по умолчанию** — `claude-sonnet-5` (как в ТЗ). Проверить, что на шлюзе это имя есть в `/v1/models`, иначе поменять `DEFAULT_MODEL`.
